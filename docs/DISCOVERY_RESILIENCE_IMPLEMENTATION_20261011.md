## Durable recovery continuation (qualification pending)

V11 adds persistent request generations, 128-attempt/24-hour job budgets, provider admission shared by authenticated subject and provider identity, durable dependency incidents and attempt history. Sharing is deliberately restricted to the same subject: tenant/dependency-wide aggregation is not claimed. One outstanding call per such scope bounds half-open recovery; unrelated subjects/providers remain independent. Default backoff is 5/15/60/300/900 seconds with positive jitter up to20%. Retry-After is never shortened; exceeding the remaining deadline pauses permanently. A restart/new job does not reset an unresolved dependency budget.

Remote search/parser work occurs outside PostgreSQL transactions. All validated candidates and SUCCEEDED are committed by one final request-generation/live-lease CAS. Expired/replaced/cancelled workers cannot publish or resolve dependency evidence. The old unversioned completion function now rejects callers. Intermediate provider results are discarded if another required provider fails; no partial set is published/adoptable. Transport-local sleeping/retries/circuits are removed to avoid multiplying or resetting the owner's durable policy. Provider status is caller-scoped persisted evidence and reports NOT_OBSERVED rather than inventing health.

Profile v1 is fixed at128 attempts/24hours, request leases at120s,64 candidates/provider and256/request; publication retains the existing24h technical cache TTL. An attempt admitted within the final budget may succeed; failed/exhausted sessions cannot be silently restarted. Successful read-only provider recovery resolves the same incident, preserves all attempt history and cumulative counts, and permits a new fault episode. Unknown/TLS/identity failures block; interruption cancels the job. DB failures leave the current lease to expire; they do not authorize a successful result.

New PostgreSQL/Java tests cover generation and lease expiry, cancellation during work, atomic rollback, shared incident dedup, full Retry-After, exhaustion across jobs/restarts, isolation, concurrent admission, stale provider tokens and restart recovery. These are unqualified until the current SHA's module workflow completes.
