# R1b owner enforcement — PET mapping

Normative sources: Authorization 1.5 §§109.2–109.3, 36.10 (owner-side DAL), 34.2 (operational detail and denial semantics); Semantic 1.3 §65/§160.7. This follow-up closes the code boundaries identified in the previous R1b endpoint audit. Real IAM/workload/THS browser acceptance remains AUT-04/R6.

Shared SDK 1.2 adds `OwnerAuthorization`, a request-bound evaluator using the exact same immutable snapshot as servlet authentication. `candidates()` is admission only: it checks declared actor/scope and MUST NOT authorize release. `decide`/`require` is called with owner-resolved resource metadata before each output. No directory or remote PDP lookup occurs in this path. Raw capability/label headers and coarse attributes remain non-authoritative.

Every registered `/api/semantic/v1/**` handler must declare `SemanticCapability`; an undeclared route denies. The interceptor runs before controller argument binding and calls the local owner evaluator using module=SEMANTIC, the route's resource identifier and a controller-specific resource type (`semantic.artifact`, `semantic.discovery`, `semantic.validation`, `semantic.interchange`, `semantic.governance`, `semantic.changegovernance`). These are explicit policy resource names; legacy broad grants remain supported, resource-constrained grants must name the correct type.

Capability IDs retain the deployed `ouf.semantic` prefix. `read` consults published content; `search` is separate; `discovery` covers request/candidate/provider reads; `propose` covers draft/import/adoption/change proposals; `review.prepare` covers validation/impact preparation; `approval.request` remains the existing request capability; consumer-reference write keeps its own capability. Draft artifact/search access additionally requires `propose` or `review`. Existing trusted-human approve/publish/lifecycle routes keep their independent HUMAN and per-operation guards. No machine inherits a human approval privilege.

`evidence/semantic-route-authorization-v1.json` records the declarations. HttpApiRuntimeTest exercises every registered route with a trusted principal lacking its grant, plus anonymous/coarse-forged reads and writes, draft separation and the positive publication lifecycle. Production policies must declare newly separated search/review.prepare capabilities with the matching canonical scopes (`semantic.search`, `semantic.review`); no wildcard grant or implicit permission inheritance is added.
