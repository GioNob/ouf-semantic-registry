# Durable native semantic preparation

Gateway-mediated MCP preparation now has a bounded owner API for native DRAFT creation, validation, review request and receipt reconciliation. Each logical batch uses the same proposalKey across attempts. PostgreSQL atomically persists commands and effects, serializes duplicate transitions, rejects changed intent and scopes reads to verified tenant/principal. An interrupted transaction rolls back all its effects; a lost committed response is recovered by proposal read. Editing a revision invalidates the next transition. Validation warnings remain visible.

Review requires a current PASS validation and its exact content hash. The existing challenge entry point now enforces this guard as well. All batch challenges commit atomically and return real revision IDs, hashes, expiry and trustedApprovalRef values. Replays return the original receipt; they never extend expired challenges or claim approval. Phase is a preparation receipt, not a fresh domain lifecycle/approval observation. HUMAN decisions and publication remain solely in the existing THS. No source activation or ingestion occurs.

V10 adds owner-local receipts. Receipt retention is currently indefinite; cleanup/capacity tuning and timed challenge renewal are not implemented. There is no new automatic retry worker or budget reset: ambiguous outcomes are reconciled through the receipt, and explicit owner/authorization/configuration errors block further dependent work. Runtime automatic pause/resume qualification is separate from transactional deduplication. Do not claim platform resilience compliance or production rollout from these tests.

Tests exercise real PostgreSQL transactions, concurrent create/review, mid-batch rollback, reconstructed service receipt reads, immutable intent, stale revisions, failed validation and incorrect hashes. The focused cross-module workflow also runs actual Gateway Lua receipts against this Java owner and fresh local Authorization. Identity/policy remain synthetic fixtures; target custody, migrations, routes, policy publication and THS rendering are unproved until independently observed.

This change is stacked on the current semantic consultation delivery branch rather than replacing main with the deployed historical source line. Preserve the separate resilience/source-read changes when assembling a release. Teatri's retained 21 commands remain proposals; no production revision/challenge is fabricated by this implementation.
